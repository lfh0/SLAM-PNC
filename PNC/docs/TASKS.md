# 端到端局部规划器任务分解（冻结版）

## 1. 文档状态

- 状态：冻结基线
- 对应需求：`docs/REQUIREMENTS.md`
- 任务范围：基础工程改造、训练、推理三个大模块
- 实施原则：先完成无网络闭环，再训练模型，最后接入在线推理

本文档用于固定当前项目的实施边界、模块依赖、交付物和验收门槛。后续若修改网络输入输出、坐标系、时间语义或控制接口，必须同步更新 `REQUIREMENTS.md` 和本文档，并记录变更原因及受影响的数据、模型和代码。

## 2. 总体任务关系

```text
模块一：基础工程改造
    ├── 为训练提供统一坐标、时间、数据预处理和专家轨迹
    ├── 为推理提供轨迹适配、安全检查、MPC和降级能力
    └── 先通过无网络10 Hz滚动闭环
                 |
                 +----------------------+
                 v                      v
模块二：训练                         模块三：推理
原始数据 -> 样本 -> 标签 -> 模型      在线输入 -> 模型 -> 安全轨迹 -> MPC
                 |                      ^
                 +---- 导出模型与配置 ---+
```

依赖约束：

1. 模块一的接口冻结是模块二和模块三的共同前置条件；
2. 模块一未通过无网络闭环验收前，不允许让网络轨迹控制车辆；
3. 模块二未产出通过离线评测的模型前，模块三只实现框架和回放测试，不进入闭环接管；
4. 训练与推理必须复用相同的预处理实现、配置和坐标定义；
5. 网络轨迹必须经过轨迹适配器和 Safety Checker，禁止直接进入 MPC。

# 3. 模块一：基础工程改造

## 3.1 模块目标

在没有训练模型的条件下，使用确定性局部轨迹源打通以下闭环：

```text
Super-LIO + 全局路径
 -> 确定性局部轨迹
 -> 轨迹适配器
 -> Safety Checker
 -> MPC滚动更新
 -> 底盘控制/仿真执行
```

该模块完成后，神经网络只需替换确定性轨迹生成器，不应再次修改控制、安全和消息链路。

## 3.2 任务清单

### B-01 冻结坐标系、时间和车辆参数

任务：

- 冻结规划控制TF为 `map -> world -> robot -> imu`；
- 冻结 `robot = IMU中心 = 车辆旋转中心 = 规划与控制参考点`；
- 保持LIO估计链与Gazebo真值车模链独立，不发布二者之间的绑定TF；
- 统一使用传感器采样时间，不用消息到达时间代替；
- 当前仿真MPC轴距统一为 `0.4 m`；
- 固定正向/倒车速度符号和角度正方向。

交付物：

- `docs/DECISIONS.md`中的F1坐标、参考点和状态来源决策；
- 修正后的MPC轴距配置；
- Super-LIO运行态接口核验结果。

验收：

- 有效传感器时间可查询 `map -> robot` 和 `map -> imu`；
- TF树无重复父节点和重复发布者；
- `/lio/robo/odom`和`/lio/cloud_imu`持续输出，frame与冻结方案一致；
- MPC轴距与当前仿真车辆轴距一致。

依赖：无。

### B-02 分离全局任务与滚动局部轨迹

任务：

- 独立维护 `mission_goal` 和 `local_horizon_end`；
- 局部轨迹更新不得修改全局任务终点；
- 只有局部轨迹包含真正终点且车辆满足到达条件时，才进入任务完成状态；
- 全局路径重规划不得被控制器误判为新任务。

交付物：任务目标接口、局部轨迹语义和到达状态机。

验收：连续更新3秒局部轨迹时，任务终点和完成状态不被反复重置。

依赖：B-01。

### B-03 改造MPC滚动轨迹接口

任务：

- 将完整重置拆分为 `startMission()`、`updateLocalTrajectory()` 和 `cancelMission()`；
- `updateLocalTrajectory()`只原子替换未来参考轨迹；
- 新轨迹到达后在整条短轨迹中重新进行位置和航向联合匹配；
- 保留控制状态、任务目标、上一控制量、求解器热启动和到达状态；
- 正常局部轨迹更新不得触发起始航向调整或停车；
- 将阻塞式状态切换停车改为非阻塞状态机；
- 轨迹更新和控制计算之间保证线程安全。

交付物：改造后的MPC接口、状态机和单元测试。

验收：

- 局部轨迹以10 Hz更新时，MPC以50 Hz连续运行；
- 最近点不因每次更新固定回到索引0；
- 更新轨迹不会阻塞控制循环；
- 控制量在新旧轨迹切换处连续且满足变化率限制。

依赖：B-01、B-02。

### B-04 定义统一的原始局部轨迹协议

第一版固定字段：

```text
observation_stamp
frame_id = base_link(t_obs)
dt
x[] / y[] / velocity[]
confidence
stop_probability
contains_mission_goal
source
sequence_id
```

固定语义：

- 网络或基线输出15个未来点；
- 第 `i` 点对应 `t_obs + (i + 1) * 0.2 s`；
- 坐标位于 `base_link(t_obs)`；
- 第一版可使用绝对局部坐标 `[x,y,v]`，如改为增量坐标必须同步修改需求、数据集和模型版本；
- 原始局部轨迹不是最终 `RobotTrajectory`。

交付物：ROS消息定义或等价内部数据结构、字段说明和序列化测试。

验收：确定性基线、训练标签和在线推理能够使用同一协议。

依赖：B-01。

### B-05 实现轨迹适配器

任务：

1. 检查点数、时间、数值、坐标和速度范围；
2. 使用 `t_obs` 对应位姿将局部轨迹转换到 `map`；
3. 按 `t_exec - t_obs` 裁掉已经过期的轨迹前段；
4. 预测MPC开始执行时的车辆状态；
5. 构造当前状态到剩余轨迹的短连接段；
6. 平滑并按MPC所需分辨率重采样；
7. 确定性计算 yaw、四元数、弧长、曲率、角速度、加速度和 jerk；
8. 填充完整 `RobotTrajectory`；
9. 处理低速、重复点和除零退化情况。

交付物：轨迹适配库、参数配置、单元测试和可视化工具。

验收：

- Ego到Map转换通过已知轨迹测试；
- 输出时间和弧长单调；
- 所有字段有限；
- `omega = v * curvature` 在允许误差内成立；
- 存在推理等效延迟时，轨迹不会回跳到历史起点。

依赖：B-01、B-04。

### B-06 实现Safety Checker

任务：

- 检查NaN、Inf、点数和时间单调性；
- 检查轨迹年龄、定位、点云和TF新鲜度；
- 检查起点连续性以及新旧轨迹跳变；
- 检查速度、加减速度、曲率、转角、转角变化率和 jerk；
- 使用车辆完整 footprint 和相邻点 swept volume 检查静态碰撞；
- 为动态障碍预留时空占用接口，第一版目标为可靠减速或停车；
- 返回结构化拒绝原因，不只返回布尔值。

交付物：Safety Checker库、拒绝原因枚举、测试场景。

验收：能够稳定拒绝陈旧、跳变、碰撞、数值异常和运动学不可执行轨迹。

依赖：B-01、B-05。

### B-07 实现Watchdog和受控制动

任务：

- 监控定位、点云、轨迹、规划器和控制器的最后有效时间；
- 实现 `NORMAL -> DEGRADED -> DECELERATING -> STOPPED -> EMERGENCY` 状态；
- 短时失败可使用上一条仍有效轨迹并限速；
- 连续失败生成满足减速度和转角连续性的制动轨迹；
- 规划器或网络进程退出后，watchdog仍独立工作；
- 初始轨迹年龄阈值采用需求文档建议值，并通过实测调整。

交付物：独立安全状态机、制动轨迹生成器和诊断话题。

验收：停止发布轨迹后，车辆不会无限沿旧轨迹运行，并能按约束平滑停车。

依赖：B-03、B-05、B-06。

### B-08 实现轨迹源管理

任务：

- 支持 `minco`、`baseline`、`neural` 三种来源；
- 任一时刻只允许一个来源发布最终控制参考轨迹；
- 统一向MPC发布 `/controller/reference_trajectory`；
- 通过launch参数选择来源；
- 提供来源状态和冲突检测。

交付物：轨迹选择节点或等价机制、launch配置。

验收：MINCO与神经规划器不会同时驱动MPC，并能安全切回传统链路。

依赖：B-03、B-04。

### B-09 实现确定性局部轨迹基线

任务：

- 从MINCO优化后的全局轨迹提取固定局部时域；
- 转换到 `base_link(t_obs)`；
- 根据路径曲率和车辆约束生成速度；
- 输出B-04定义的统一原始局部轨迹；
- 以10 Hz稳定更新。

交付物：无网络基线生成器和对应launch文件。

验收：可替代未来网络输出，通过适配器、安全检查和MPC完成闭环。

依赖：B-01、B-04。

### B-10 基础工程集成验收

测试：

- 直线、转弯、停止和最终目标到达；
- 10 Hz轨迹更新与50 Hz控制；
- TF短时缺失、输入缺帧、轨迹断流；
- 非法轨迹、碰撞轨迹和轨迹跳变；
- 定位跳变与时间倒退；
- 传统MINCO和基线模式切换。

完成标准：

- 无训练模型也能稳定运行完整局部规划控制链；
- 轨迹更新不重置MPC任务状态；
- 所有异常均有诊断、拒绝或安全降级路径；
- 自动化测试和测试记录可复现。

依赖：B-01至B-09。

## 3.3 可独立验证的小模块划分

模块一按下列七个小模块实施。每个小模块必须提供正常输出、诊断输出和独立测试入口；前一模块未通过验收，不进入依赖它的车辆闭环测试。

### F1 坐标、时间与车辆状态基础层

覆盖任务：B-01。

功能边界：复用Super-LIO已有定位、TF和带时间戳状态输出，不重复建立车辆状态节点，不生成轨迹。

输入：

```text
/lio/robo/odom             nav_msgs/Odometry，world -> robot
/lio/cloud_imu             sensor_msgs/PointCloud2，imu坐标系
/tf、/tf_static            map -> world -> robot -> imu
```

正常输出：

```text
Super-LIO原始输出直接作为后续模块输入
TF查询接口：lookup(map, robot/imu, message_stamp)
冻结的车辆参考点语义和MPC轴距配置
```

诊断依据：话题频率、消息延迟、frame语义和TF可查询性。更高层的数据过期、轨迹年龄和故障降级分别在F4、F5和F6实现。

独立验证：

1. 检查 `/lio/robo/odom` 的频率、延迟、`header.frame_id` 和 `child_frame_id`；
2. 检查 `/lio/cloud_imu` 的频率、延迟和 `frame_id`；
3. 查询 `map -> robot`、`robot -> imu` 和 `map -> imu`；
4. 确认LIO估计链与Gazebo真值链保持独立；
5. 检查MPC轴距与仿真车辆配置一致。

通过标准：

- `/lio/robo/odom`和`/lio/cloud_imu`持续有效；
- `map -> world -> robot -> imu`可查询；
- `robot`物理语义已冻结；
- 未引入LIO估计与Gazebo真值之间的绑定TF；
- MPC轴距已修正为当前仿真车辆的 `0.4 m`。

### F2 MPC任务与滚动参考控制层

覆盖任务：B-02、B-03。

功能边界：只接收已经合法、位于 `map` 且字段完整的 `RobotTrajectory`；不负责局部坐标转换、碰撞检查或网络推理。

输入：

```text
startMission(mission_goal)
updateLocalTrajectory(RobotTrajectory in map)
cancelMission()
`/lio/robo/odom`
```

正常输出：

```text
ControlCommand
ControllerState
TrackingDiagnostics
├── mission_id
├── trajectory_sequence_id
├── matched_index
├── tracking_error
└── solver_status
```

诊断输出：空轨迹、轨迹耗尽、求解失败、状态不允许更新、任务未启动和控制周期超时。

独立验证：使用专用测试发布器直接生成完整的 `map` 坐标 `RobotTrajectory`，绕开BEV、基线、适配器和Safety Checker。

测试用例：

1. 单条直线轨迹跟踪；
2. 以10 Hz发布相互重叠的滚动直线/圆弧轨迹；
3. 更新局部轨迹但保持同一 `mission_goal`；
4. 新轨迹索引与旧轨迹完全不同，验证重新匹配；
5. 前进/倒车模式切换，验证非阻塞过渡；
6. 调用取消任务，验证受控退出；
7. 在控制循环运行时并发更新轨迹，检查线程安全。

通过标准：

- 10 Hz轨迹更新下控制循环稳定达到目标频率；
- `mission_id`、任务终点和正常跟踪状态不随局部更新重置；
- 更新轨迹不触发0.5秒阻塞停车；
- 匹配点不固定回到首点；
- 控制输出有限、连续并满足变化率约束。

### F3 统一局部轨迹协议与确定性基线层

覆盖任务：B-04、B-09。

功能边界：从全局路径生成与未来网络完全同格式的原始局部轨迹，不生成 `RobotTrajectory`，不进行最终安全裁决。

输入：

```text
/trajopt/global_trajectory robot_trajectory_msgs/RobotTrajectory，map坐标系
`/lio/robo/odom`
mission_goal
局部时域、采样间隔和速度配置
```

正常输出：

```text
RawLocalTrajectory
├── observation_stamp
├── frame_id = robot(t_obs)
├── dt = 0.2 s
├── 15 × [x, y, v]
├── confidence
├── stop_probability
├── contains_mission_goal
├── source = baseline
└── sequence_id
```

诊断输出：全局路径缺失/过期、车辆偏离路径、最近进度匹配失败、未来路径长度不足及需A*重规划。

独立验证：

1. 使用人工直线、圆弧、S弯、回环和平行路径输入；
2. 验证路径截取沿进度单调前进，不选择空间相近的错误分支；
3. 验证输出点时间语义为 `t_obs + (i+1)*0.2 s`；
4. 验证从 `map` 转到 `base_link(t_obs)` 后的点位置；
5. 验证末端附近的 `contains_mission_goal`；
6. 在RViz同时显示全局路径和原始局部路径。

通过标准：

- 固定输入产生确定性输出；
- 所有输出满足B-04协议；
- 路径进度、坐标转换和终点标志单元测试通过；
- 能稳定以10 Hz发布，未来可被神经输出无缝替换。

### F4 延迟补偿与RobotTrajectory适配层

覆盖任务：B-05。

功能边界：只完成坐标、时间和几何字段适配；不判断环境碰撞，不直接发布给MPC。

输入：

```text
RawLocalTrajectory，位于base_link(t_obs)
按 `observation_stamp` 查询/缓存的 `/lio/robo/odom`
当前时刻和预计控制接管时刻 t_exec
RobotTrajectory采样参数
```

正常输出：

```text
CandidateRobotTrajectory，map坐标系
AdapterDiagnostics
├── observation_age
├── cropped_duration
├── connection_duration
├── transform_used
└── numerical_quality
```

处理顺序固定为：

```text
按t_obs转换到map
 -> 按t_exec-t_obs裁掉过期段
 -> 预测t_exec车辆状态
 -> 生成短连接段
 -> 平滑与重采样
 -> 计算yaw/弧长/曲率/omega/加速度/jerk
```

诊断输出：轨迹过期、TF不可用、剩余时域不足、无法连续连接、重复点、数值退化和字段不一致。

独立验证：

1. 构造已知Ego直线/圆弧，验证转换后的Map坐标；
2. 注入0、50、100、200、500 ms延迟，验证过期段裁剪；
3. 让车辆在适配期间运动，验证轨迹不回跳到历史起点；
4. 验证低速、重复点、短轨迹和跨 `-pi/pi` 航向；
5. 检查时间、弧长、yaw、曲率、omega、加速度和jerk关系；
6. 将输出保存为测试消息并在RViz可视化。

通过标准：

- 输出时间和弧长单调，所有字段有限；
- `omega = v * curvature` 满足误差阈值；
- 已知几何轨迹的数值误差满足测试阈值；
- 有延迟时轨迹起点与预计执行状态连续；
- 不可适配输入返回错误，不伪装修复为可执行轨迹。

### F5 确定性轨迹安全检查层

覆盖任务：B-06。

功能边界：只对候选轨迹作准入判断并返回原因；不修改轨迹来掩盖严重错误，不直接控制底盘。

输入：

```text
CandidateRobotTrajectory
`/lio/robo/odom`
静态障碍栅格/点云
可选动态障碍时序占用
VehicleModel和安全阈值
上一条已接受轨迹
```

正常输出：

```text
SafetyResult
├── accepted
├── reason_code
├── first_unsafe_index
├── minimum_clearance
└── measured_limit_values

SafeRobotTrajectory，仅accepted时有效
```

拒绝原因至少包括：陈旧、数值异常、起点不连续、轨迹跳变、静态碰撞、动态碰撞、速度超限、加速度超限、曲率/转角超限、jerk超限和制动距离不足。

独立验证：

1. 直线无障碍轨迹应通过；
2. 障碍物位于车辆中心、车角和相邻采样点之间时应拒绝；
3. 对比中心点检查与完整footprint/swept-volume检查；
4. 分别注入NaN、Inf、旧时间戳和各动力学超限；
5. 注入相邻两条左右跳变轨迹；
6. 验证每个失败用例返回唯一且正确的主要原因。

通过标准：

- 所有预定义危险轨迹100%被拒绝；
- 合法基准轨迹不被误拒绝；
- 检查耗时满足10 Hz规划预算；
- 每次拒绝都有可记录、可统计的原因和位置。

### F6 轨迹管理、唯一发布源与安全降级层

覆盖任务：B-07、B-08。

功能边界：负责选择唯一轨迹源、管理新旧安全轨迹生命周期并在故障时降级；不生成正常行驶意图。

输入：

```text
minco/baseline/neural候选来源状态
SafetyResult和SafeRobotTrajectory
`/lio/robo/odom`
传感器、定位、规划器和控制器健康状态
trajectory_source配置
```

正常输出：

```text
/controller/reference_trajectory   唯一最终轨迹
PlannerSafetyState
├── NORMAL
├── DEGRADED
├── DECELERATING
├── STOPPED
└── EMERGENCY
SourceDiagnostics
```

诊断输出：多发布源冲突、轨迹断流、轨迹过期、连续拒绝、定位/点云超时、制动轨迹生成失败和回退状态。

独立验证：

1. 同时模拟多个轨迹源，验证只选中配置来源并报告冲突；
2. 停止轨迹输入，验证短时保持、限速、受控制动的状态顺序；
3. 连续注入被拒绝轨迹，验证不会无限使用旧轨迹；
4. 模拟规划进程退出，验证watchdog仍工作；
5. 模拟定位严重失效，验证进入停车/紧急状态；
6. 验证恢复条件和人工复位规则，防止状态来回抖动。

通过标准：

- MPC任一时刻只有一个最终参考发布源；
- 轨迹断流后在规定时间内进入受控制动；
- 旧轨迹不超过有效期继续使用；
- 状态转换非阻塞并具有迟滞；
- 可以明确、安全地切回MINCO。

### F7 模块一集成与回归验证层

覆盖任务：B-10。

功能边界：不新增规划功能，只负责把F1至F6组成可复现的无网络闭环并持续回归。

输入链路：

```text

 -> F4 CandidateRobotTrajectory
```

输出：

- rosbag、测试日志和自动验收报告。

集成测试：

2. 静态障碍触发拒绝与停车；
3. 10 Hz局部轨迹与50 Hz MPC连续运行；

# 4. 模块二：训练

## 4.1 模块目标

建立从原始rosbag到可部署模型的完整、可复现训练链路。训练模块最终交付物是通过独立测试集评测的模型、预处理配置和模型说明，而不是在线控制节点。

## 4.2 任务清单

### T-01 冻结模型任务和张量规范

输入：

```text
Temporal BEV
+ Route Mask / Route Progress
+ Ego State
+ 输入有效性Mask
```

第一版建议：

- 历史帧：4帧，时刻为 `t-0.3、t-0.2、t-0.1、t`；
- BEV范围：X为 `-5～20 m`，Y为 `-10～10 m`；
- 分辨率：`0.1 m/cell`；
- 栅格大小：`250×200`；
- 每帧至少包含 Occupancy、Height、Density；
- 额外提供 Observed/Unknown 或有效性Mask；
- Ego State第一版至少包含 `[v, omega]`，建议加入转角和加速度；
- 输出遵循B-04协议。

交付物：张量维度、通道顺序、归一化参数和模型I/O版本号。

验收：同一样本经训练端与部署端处理后逐元素一致或误差在规定范围内。

依赖：B-01、B-04。

### T-02 建立原始数据采集规范

至少记录：

```text
/lio/cloud_imu
/lio/robo/odom
/astar_path
/tf
/tf_static
/cmd_vel
底盘真实速度和转角
MINCO专家轨迹
全局任务目标
规划和安全状态
```

要求保留原始时间戳、软件版本、参数配置、车辆配置和场景说明。

交付物：rosbag录制launch/脚本、元数据格式、数据完整性检查工具。

验收：录制结果可回放，并能重建TF、车辆状态、环境和专家轨迹。

依赖：B-01、B-02。

### T-03 实现离线同步与Temporal BEV

任务：

- 维护历史点云和位姿缓存；
- 插值每帧采样时刻的车辆位姿；
- 将历史帧运动补偿到 `base_link(t_obs)`；
- 完成ROI、降采样、离群点、地面和碰撞高度处理；
- 生成Occupancy、Height、Density和有效性表示；
- 固定像素原点、轴向、边界和归一化规则；
- 缺帧时填充并生成有效Mask。

交付物：可被训练和在线推理共同调用的预处理库、离线可视化和单元测试。

验收：静态障碍在运动补偿后的历史帧中保持空间对齐。

依赖：B-01、T-01、T-02。

### T-04 实现Route和Ego State样本

任务：

- 基于路径进度单调截取局部路线，避免回环或平行路段选错分支；
- 将路线转换到 `base_link(t_obs)`；
- 生成Route Mask、Progress/Direction和可选Goal Mask；
- 生成并归一化Ego State；
- 标记路径失效、车辆明显偏离和需重规划状态。

交付物：路线编码器、自车状态编码器和可视化测试。

验收：路线通道与BEV使用完全相同的栅格和坐标定义。

依赖：B-01、T-01、T-02。

### T-05 生成专家轨迹标签

第一版以现有A* + MINCO作为主要专家，并保留人工轨迹扩展接口。

任务：

- 按规划时间而非消息到达顺序匹配专家轨迹；
- 提取 `t_obs` 之后的固定未来时域；
- 转换到 `base_link(t_obs)`；
- 按0.2秒重采样15个未来点；
- 生成 `[x,y,v]` 和有效Mask；
- 使用Safety Checker过滤碰撞或不可执行标签；
- 明确停车、绕障和规划失败样本的处理方式。

交付物：标签生成器、标签质量报告和抽样可视化。

验收：标签第一点严格对应 `t_obs + 0.2 s`，不存在输入和标签时间错位。

依赖：B-05、B-06、B-09、T-02。

### T-06 构建、清洗和划分数据集

每个样本至少包含：

```text
temporal_bev
route_features
ego_state
input_valid_mask
target_trajectory
target_valid_mask
observation_stamp
source_bag
quality_flags
```

过滤TF缺失、时间不同步、定位跳变、专家失败、轨迹碰撞、输入严重缺帧和标签不足样本。按照完整路线、场景或采集批次划分训练集、验证集和测试集，禁止随机拆分连续帧。

交付物：版本化数据集、统计报告、划分清单和可复现构建脚本。

验收：数据集无相邻帧跨集合泄漏，所有样本可追溯到原始bag和配置。

依赖：T-03、T-04、T-05。

### T-07 实现最小可行模型和训练流程

第一版结构：

```text
4帧Temporal BEV + Route Mask + 输入有效性Mask
  -> 早期通道拼接 -> 单一CNN -> Scene Feature
Ego State             -> 小型MLP -> Ego Feature
Scene Feature + Ego Feature -> 非自回归Decoder -> 15×[x,y,v]
```

首版不得默认引入Transformer、ConvGRU、Cross-Attention或生成式模型；只有在相同数据划分下的消融实验证明其能显著改善独立测试集的安全通过率、轨迹跳变或遮挡场景表现时，才允许替换。损失至少包含位置、速度、航向/切向、平滑性、曲率、运动学一致性、碰撞和路径进度。第一版优先保证简单无障碍和静态障碍场景。

交付物：训练代码、配置、检查点、日志和复现实验说明。

验收：固定数据、代码、配置和随机种子后能够复现主要指标。

依赖：T-01、T-06。

### T-08 离线评测与错误分析

指标：

- ADE和FDE；
- 速度和航向误差；
- 中心线及footprint碰撞率；
- 曲率、加速度、转角和 jerk 超限率；
- 路线偏离和进度；
- 相邻样本输出跳变；
- 无障碍、弯道、静态障碍、停车等分场景指标。

交付物：独立测试集报告、失败样本集、模型准入结论。

验收：模型达到项目设定阈值且没有阻断性安全缺陷，才允许导出部署。

依赖：T-07。

### T-09 导出和冻结部署模型

任务：

- 导出ONNX，按硬件需要进一步生成TensorRT引擎；
- 对比训练框架、ONNX和TensorRT输出；
- 保存模型版本、输入输出名、张量维度、归一化、BEV和Route配置；
- 记录训练数据版本、代码提交和离线指标。

交付物：部署模型、完整配置、校验值和模型卡。

验收：不同后端输出误差在规定阈值内，模型及配置能够唯一复现。

依赖：T-08。

## 4.3 模块完成标准

- 数据采集、样本生成、训练和评测可重复执行；
- 训练/验证/测试不存在场景泄漏；
- 预处理定义与基础工程一致；
- 产出一个通过准入评测、可部署且可追溯的模型版本。

# 5. 模块三：推理

## 5.1 模块目标

将模块二产出的冻结模型接入实时系统，保证在线输入与训练一致，并通过延迟补偿、轨迹适配、安全检查和MPC滚动接口完成安全闭环。

## 5.2 任务清单

### I-01 实现在线输入流水线

任务：

- 实时同步点云、位姿、全局路径和车辆状态；
- 复用T-03、T-04的预处理库与T-01配置；
- 生成Temporal BEV、Route、Ego State和有效Mask；
- 检查数据年龄、TF和定位状态；
- 发布调试图和输入诊断。

交付物：在线预处理节点和训练/部署一致性测试。

验收：同一段rosbag的离线样本与在线回放输入一致。

依赖：B-01、T-01、T-03、T-04。

### I-02 实现推理引擎

任务：

- 加载冻结的ONNX或TensorRT模型；
- 完成模型预热、输入维度检查和输出有限性检查；
- 统计预处理、推理、后处理的平均、P95和最坏耗时；
- 使用“只保留最新输入”队列，禁止旧输入无限排队；
- 捕获模型加载、推理超时和运行时异常；
- 发布模型版本和健康状态。

交付物：推理节点、性能报告和异常测试。

验收：持续输入下无队列积压，推理输出携带原始 `t_obs` 和模型版本。

依赖：I-01、T-09。

### I-03 发布统一原始预测轨迹

任务：

- 将模型输出封装为B-04统一协议；
- 保留 `observation_stamp` 和 `base_link(t_obs)`；
- 发布原始轨迹、置信度、停止概率和可视化路径；
- 不在推理节点中直接构造最终控制消息或调用MPC。

交付物：原始预测轨迹发布接口和可视化。

验收：推理输出可以无缝替换B-09确定性基线输出。

依赖：B-04、I-02。

### I-04 完成延迟补偿和安全轨迹生成

任务：

- 以 `current_time - observation_stamp` 计算完整数据年龄；
- 使用B-05完成Ego到Map转换、过期段裁剪、执行状态预测和连接段生成；
- 使用B-06检查合法性、运动学、连续性和碰撞；
- 根据轨迹年龄和检查结果接受、拒绝或降级；
- 禁止通过整体平移把历史轨迹起点强行对齐当前车辆。

交付物：安全 `RobotTrajectory` 和完整拒绝原因。

验收：人为注入不同推理延迟时，不出现轨迹回跳；超出阈值的结果被拒绝并触发正确降级。

依赖：B-05、B-06、B-07、I-03。

### I-05 接入MPC滚动闭环

任务：

- 通过 `updateLocalTrajectory()`以约10 Hz更新参考轨迹；
- MPC保持约50 Hz独立控制；
- 使用B-08保证神经轨迹是唯一有效轨迹源；
- 网络异常时由B-07处理短时保持、限速或停车；
- 保留快速切回MINCO的能力。

交付物：神经规划launch和闭环状态诊断。

验收：网络轨迹更新不触发任务重置、阻塞停车或控制跳变。

依赖：B-03、B-07、B-08、I-04。

### I-06 完成影子模式

运行方式：

```text
MINCO继续控制车辆
神经网络并行实时推理
网络轨迹经过Safety Checker但不进入MPC
```

统计推理时延、安全通过率、拒绝原因、与专家轨迹差异、轨迹连续性和输入缺失率。

交付物：影子模式launch、运行日志和准入报告。

验收：完成规定里程/时长和场景覆盖，且关键指标达到项目准入阈值。

依赖：I-01至I-04。

### I-07 分级闭环测试与实车部署

顺序：

1. rosbag回放；
2. 仿真闭环；
3. 架空轮或台架测试；
4. 封闭场地低速无障碍；
5. 静态障碍绕行与回归；
6. 动态障碍可靠减速和停车；
7. 通过安全评审后逐步扩大速度和场景。

每个阶段必须配置人工急停、自动watchdog、速度上限、日志、rosbag和一键传统方案回退。

交付物：各阶段测试报告、失败Case和准入记录。

验收：只有通过当前阶段验收后才能进入下一阶段；第一版动态障碍以可靠减速和停车为完成目标。

依赖：I-05、I-06。

## 5.3 模块完成标准

- 在线输入与训练预处理一致；
- 推理无输入积压，最坏时延处于可接受范围；
- 历史观测产生的轨迹经过时间裁剪和状态拼接；
- 所有网络轨迹经过Safety Checker；
- MPC不因10 Hz更新反复重置；
- 推理超时、轨迹断流和进程退出均能受控停车；
- 支持安全切回传统MINCO方案。

5. 完成I-01至I-04，只做回放和影子评估；
6. 影子模式通过后完成I-05至I-07，逐级进入闭环测试。

# 8. 冻结项与变更控制

以下内容一旦进入数据采集或训练阶段即视为冻结项：

- TF树和车辆控制参考点；
- BEV物理范围、分辨率、像素方向和通道定义；
- 历史帧数量及时间间隔；
- Route与Ego State字段、顺序和归一化；
- 网络输出坐标系、点数、时间间隔和字段语义；
- `mission_goal`与`local_horizon_end`的接口语义；
- `RobotTrajectory`字段定义；
- Safety Checker车辆参数和基本限制。

任何冻结项变更必须记录：

```text
变更内容
变更原因
影响的数据集版本
影响的模型版本
影响的在线配置与接口
需要重新执行的测试
```

未经评审不得让训练代码和在线推理分别维护两套同名但实现不同的预处理逻辑。

# 9. 模块四：传统局部避障重规划与训练教师

## 9.1 模块目标

在保持全局A*/Hybrid A*与全局MINCO低频工作的前提下，针对局部代价地图中的新静态障碍生成可执行、平滑且能重新汇入全局参考的局部绕障轨迹。该模块既是在线传统避障能力，也是模块二的绕障专家标签来源；不替代F4、F5、F6和MPC。

## 9.2 子模块与依赖

| 编号 | 子模块 | 输入 | 输出 | 独立验收 |
| --- | --- | --- | --- | --- |
| LA-00 | MINCO可复用核心 | 现有全局MINCO、走廊构建、车辆约束与全局回归样例 | 不依赖ROS话题的`minco_core`库；全局节点保持原接口 | 同一输入下全局MINCO输出点数、时间单调性和主要状态一致；现有全局启动链路不回归 |
| LA-01 | 参考窗口与重汇入目标 | 全局MINCO、F3进度、odom、局部地图范围 | 单调局部窗口、重新汇入候选状态 | 回环/平行路径不跳支；终点在局部地图内且位于障碍之后 |
| LA-02 | 阻断检测与触发器 | 最新local_costmap、当前安全参考 | `NORMAL/REPLAN_REQUIRED/BRAKE_REQUIRED` | 无障碍不误触发；障碍覆盖footprint或swept volume时触发 |
| LA-03 | 局部Hybrid A*搜索 | 预测起点状态、重汇入状态、local_costmap、车辆模型 | 有方向和曲率约束的局部几何路径 | 直线、左右绕障、窄通道和无解场景均有确定结果与耗时上限 |
| LA-04 | 非零边界局部MINCO | LA-03路径、局部安全走廊、起终点P/V/A状态 | 平滑局部候选轨迹 | 起终点位置、速度、加速度连续；速度/曲率/jerk满足车辆约束 |
| LA-05 | 轨迹仲裁、安全复检与降级 | 正常F3轨迹、LA-04候选、F5结果、最新地图 | 唯一`/local_planner/raw_trajectory` | 通过候选无跳变接管；无解或超时进入受控制动，不发布多源轨迹 |
| LA-06 | 回归与训练标签 | LA-02至LA-05状态、rosbag | 绕障回归报告、T5可用专家标签 | 绕障后回归全局参考；停车与绕障标签分类正确 |

## 9.3 运行关系

```text
全局路径 → 全局MINCO → F3正常局部参考
                         │
local_costmap ──→ LA-02 阻断检测
                         │（被阻断）
现有trajopt ─────→ LA-00 minco_core
odom + 全局参考 ─→ LA-01 窗口/重汇入
                         ↓
                  LA-03 局部Hybrid A*
                         ↓
                  LA-04 局部MINCO
                         ↓
                  LA-05 F3唯一输出仲裁 → F4 → F5 → F6 → MPC
```

## 9.4 准入规则

1. 在未完成LA-02的最新地图复检和LA-05受控制动前，不允许用局部重规划替换当前安全轨迹；
2. 局部轨迹必须使用实际/预测起点状态和参考重汇入终点状态，不能默认首尾零速度；
3. 规划未在截止时间内产出安全候选时，安全优先于绕行，不得延长旧轨迹的有效期规避超时；
4. 在线绕障与离线标签生成复用相同的LA-01至LA-04核心算法和车辆参数；
5. 当前模块只承诺静态局部障碍绕行；动态障碍的第一版策略仍是减速/停车。

## 9.5 实施与验收顺序

`LA-00 → LA-01 → LA-02 → LA-03 → LA-04 → LA-05 → LA-06`。

每个子模块只能在上一项独立验收通过后进入下一项。LA-01与LA-02可共享同一份局部地图录包进行验收，但LA-03不得在LA-01的重汇入状态定义冻结前接入；LA-04不得在LA-00全局回归通过前复用MINCO代码；LA-05是唯一允许改变在线轨迹来源的步骤。
